# 发布前安全与隐私检查

本项目以MIT许可允许复用；许可证署名为 `model-service-kit contributors`。
许可证许可不等于允许公开开发者的密钥、配置、日志或个人信息。

## 允许进入源码仓库

- `src/`、`tests/`、`examples/`、`tools/`、`distribution/`。
- 项目README、操作与接口文档、许可证、构建元数据和忽略规则。
- 通用API说明、官方文档链接、回环地址及明确虚构的测试凭据。

测试中的 `secret`、`not-a-key`、`example.test` 等只用于验证拒绝／脱敏行为，
不能替换成真实密钥或真实用户配置。默认不运行真实模型测试。

## 禁止进入源码或分发包

- 用户的模型配置（包括私人服务地址、账号和凭据引用）、API Key、Token。
- 系统凭据库导出、`.env`、证书私钥和带认证参数的真实URL。
- 真实请求／回复日志、数据库、GUI截图、个人设备路径与环境清单。
- venv、pip安装记录、`direct_url.json`、构建缓存及其他项目的Git历史。
- 安全审计原始报告中的私人路径或身份信息；审计报告应保存在仓库外。

`.gitignore`只是保护措施，不保证历史提交或分发包一定安全。

## 每次公开上传前的门禁

1. 确认Git暂存区和待发布提交的完整文件清单，而不只扫描工作目录。
2. 扫描密钥／私钥、邮箱、个人路径、非示例URL；逐项检查并说明误报。
3. 检查作者和提交者姓名／邮箱；使用经本人批准的公开昵称及GitHub no-reply邮箱。
4. 新项目从干净历史开始，不复制原项目`.git`；避免把旧提交中的信息一并发布。
5. 检查wheel／源码压缩包、包元数据和交付附件，不能只检查Python源文件。
6. 验证配置和密钥未被复制、测试只使用临时配置和受控服务。
7. 向项目负责人展示文件清单、扫描结论、例外项及待上传目标，确认后才能上传。

静态扫描不能证明绝对没有敏感信息。若真实密钥曾经公开，删除文件或重写历史
不能代替在服务端撤销／轮换密钥。

## 已知测试与检测规则匹配

- `tests/test_secure_config.py`中的虚构测试域名及URL用户名／密码，用于验证
  拒绝带认证信息的地址，不是真实账号或邮箱。
- `tests/test_streaming.py`中的故意无效URL，用于验证错误分类，不是服务端地址。
- `tools/release_audit.py`的个人路径检测表达式会匹配表达式自身，
  不是开发者的真实目录。扫描仍保留该发现供人工解释，不静默隐藏。

这些示例可保留，不代表任何后续匹配都可以自动放行。

## 安装验证

`tools/verify_model_service_install.py`仅在临时配置和回环HTTP服务上验证安装。
其报告包含解释器、安装路径及依赖版本，因此应输出到仓库外，不能直接作为公开附件。
GUI测试也必须使用假凭据后端，不访问开发者真实凭据库。

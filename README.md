# Model Service Kit

独立的 Python 模型配置GUI与文本调用SDK。采用 [MIT许可证](LICENSE)，版权署名为 `model-service-kit contributors`。

源码、测试、构建工具与手册均在本仓库。项目不附带用户配置、真实密钥、模型权重或运行日志；公开上传前的检查规则见[发布安全清单](docs/publishing-security.md)。

此包可由其他 Python 项目单独安装。它保存当前用户的模型服务配置，通过 Chat Completions API 发送文本消息，并提供一个小型桌面配置界面。它不导入 NPC 代码，也不理解 R 区域、C 连接、认知候选或状态提交。

## 0.1.0普通wheel交付

本包首次分发版本为`0.1.0`，与NPC版本独立；本地构建、验证，不等于已上传PyPI或创建GitHub Release。Windows／Python 3.12为本轮安装验收范围。普通wheel包含配置GUI、凭据模块和调用SDK，不包含Python、Tk、依赖wheelhouse、NPC、模型权重、用户配置或密钥。

- [安装、启动、升级及跨设备迁移](docs/installation.md)：安装到目标项目自己的环境，不绑定开发机盘符；独立交付启动脚本不寻找开发者工作区。
- [其他Python项目接入及旧模型调用改写](docs/integration.md)：保留业务上下文／JSON解析，只替换配置读取及调用入口，含可运行示例。
- [公共接口](docs/interface.md)：流式正文／实际终态、配置快照、凭据、安全和兼容范围。

正式交付目录包含wheel、本手册、上述三份说明、示例、独立启动脚本及SHA256清单；不要求其他用户克隆整个NPC仓库。安装方法见安装手册，**不要把本地wheel名称当作已经发布在PyPI的项目直接安装**。

## 当前能力与边界

- 使用HTTPX异步接收Chat Completions SSE，正文增量即时交付；不拼装NPC区域JSON、不注入提示词、不自动附加历史消息，不启动HTTP代理。
- 单个调用句柄、一个事件消费者及唯一实际终态；区分正常、截断、拒绝、取消和网络／超时／HTTP／协议故障，不自动重试或切换模型。
- GUI与调用程序默认读取同一系统用户的配置文件；自定义路径须双方保持一致。参数元数据明文保存，API Key仅保留系统库／进程凭据引用；已有schema_version=2配置无需因安装0.1.0迁移。
- 依赖httpx>=0.28,<0.29和keyring>=25,<26；普通安装可能下载依赖。GUI还需要目标Python提供可用Tk，wheel不包含Python环境。独立进程直接调用模型，打包不增加运行时转发层。
- 程序验证使用临时配置／受控响应；安装或打开GUI不自动访问真实模型，也不操作用户旧密钥。NPC认知初测和性能结果属于NPC项目，不是本包的通用模型能力保证。

## GUI使用

先按安装手册安装wheel，再使用那个环境的Python启动：

```powershell
python -m model_service.gui
```

也可以双击[打开模型配置](open-model-config.cmd)。脚本优先使用MODEL_SERVICE_PYTHON指定的解释器，其次本目录`.venv\Scripts\python.exe`，最后PATH中的python；须预先在该环境安装本包，不是免安装EXE。不会寻找其他项目的开发环境。双击默认打开当前用户配置，指定隔离文件则按下方命令启动；启动本身不调用模型。

窗口顶部显示当前配置文件完整路径。“选择文件”打开已有文件；“新建文件”选择不存在的路径，实际保存时才创建。切换文件不复制原配置或凭据，未保存输入须确认后才丢弃。鼠标悬停字段名称、输入框和按钮约半秒，或键盘聚焦输入框，可查看用途、示例和留空含义；“使用说明”打开可滚动中文帮助。

1. 点击“新增”，填写配置标识、显示名称、服务根地址和模型名称。本地／网络服务共用一套界面；客户端补上/chat/completions，地址不应重复带此路径。
2. 本地无认证服务的密钥留空；需要密钥时输入“新密钥”，选择“系统凭据库”或“仅本次进程”。密钥不会回显，系统库失败会报错，不自动降级。
3. 高级配置可折叠：温度、输出上限、思考参数JSON可留空；连接／读取空闲超时默认10／60秒。上限字段由用户按服务文档选标准或兼容字段，不猜测模型支持能力；空参数不会发送。
4. 点击“保存配置”，再点击“设为活动模型”。修改后的配置需先保存；切换活动配置不改变已取得的快照。保存与切换都不会发起模型请求。
5. 编辑时密钥框留空保留原引用；需要取消认证时显式勾选“清除当前配置的密钥引用”。删除配置有确认框，不立即删除历史密钥，避免破坏已冻结调用。

密钥操作互斥：勾选清除会清空新密钥输入；再次输入新密钥会取消清除。不要把环境变量或普通JSON当作加密凭据库；本包的系统凭据方式由操作系统保护，运行时仍在内存使用密钥，不能防住所有同用户权限的恶意程序。

### 主程序复用GUI配置

GUI保存的配置可以被使用本包的Python程序读取，无需复制服务地址、模型名称或密钥到主程序。默认读取同一操作系统用户的配置文件；GUI选择过自定义文件时，程序须显式使用相同文件路径。

```python
from model_service import ModelService

service = ModelService()
profile = service.active_profile()  # 读取GUI保存并设为活动的配置；此处不调用模型。
```

在异步运行代码中，将业务消息和该快照交给service.start(messages, profile=profile)，再消费句柄事件。也可以通过service.store.get(profile_id)选择已保存的指定模型，不修改活动选择。已有快照不随GUI后续编辑改变；新一轮重新读取才取得最新配置。

连续调用应在同一个事件循环内复用服务，并在退出时关池；不要每次都创建服务对象。以下仅定义调用示例，不会自行执行请求：

```python
async def run_requests(requests):
    async with ModelService() as service:
        for messages in requests:
            profile = service.active_profile()
            handle = service.start(messages, profile=profile)
            try:
                async for event in handle.events():
                    yield event
            finally:
                await handle.cancel()
```

也可在调用方finally中await service.aclose()，但须在其所属事件循环退出前完成。单次请求结束／取消只释放本次响应，正常连接可回池；服务关闭才统一关池。池不保存Cookie或认证头，不携带上次消息。GUI连接测试每次独立线程／服务，仍为单次诊断，不保证取得连续主程序调用同样的优化幅度。连接复用不保证整轮显著提速。

2026-10-18补充：NPC认知测试窗口跨任务及人工批准后的第二轮复用后台服务，客户端空闲复用有效期300秒；本包默认仍为5秒，服务端可能更早断开。可选诊断新增真实TCP／TLS阶段与供应商返回的输入缓存token量，未提供不补零，不改变正文事件或`usage`契约。配置GUI的短消息测试仍独立，具体字段和边界见[公共接口](docs/interface.md)。

目标Python环境须安装本包，且本地模型服务须已启动。独立GUI与主程序跨进程使用网络密钥时须选系统凭据库，并在同一系统用户下运行；“仅本次进程”密钥不跨进程共享，换设备需重新配置凭据。读取配置及NPC专用适配已实现；其他项目首次接入仍需按接入手册改写调用入口，保存GUI配置不会自动改造其他程序。连接测试的64 token限制仅作用于测试请求，不是正式调用的固定上限。

### 本地／网络填写示例

| 字段 | 本地Ollama | 网络兼容服务 |
| --- | --- | --- |
| 配置标识／显示名称 | local-qwen／本地模型 | network-model／网络模型 |
| 服务根地址 | http://127.0.0.1:11434/v1 | https://你的服务域名/v1，以提供方文档为准 |

高级参数留空不发送，由服务默认值决定；连接／读取超时留空使用10／60秒。思考参数只填服务支持的JSON，不能据模型名称猜测。保存和活动选择均不表示已连接；GUI不启动本地模型服务，也不会自动接管其他项目。

### 独立连接测试

1. 先保存当前配置。未保存或有修改时，测试被阻止；无需设为活动模型。
2. 点击“连接测试”，阅读真实调用／可能计费提示后确认。取消确认不发送请求。
3. 程序只发送一条user短消息“这是独立连接测试。请只回复：连接正常。”，不带NPC背景、记忆、历史或业务标识。
4. 本次输出token上限取保存值与64的较小值，原值为空则64；其他生成设置保留。总时限30秒，连接／读取空闲超时仍按保存配置约束；不自动重试。以上均不写回文件。
5. 收到非空正文且正常结束才通过，不要求逐字回复；截断、拒绝、断流、超时不通过。思考模型可能因64 token不足而截断，表示链路有响应，不代表完整调用检查通过或地址不可达。
6. 右侧独立诊断面板显示进度条、已用时间、被测配置标识、首片正文时间、总耗时及字符数；默认不采集生成内容，可选内存查看见下文。测试不改变活动模型或NPC状态；编辑表单后显示未验证，旧结果不冒充新配置已通过。
7. 等待时窗口仍可响应，点击“取消测试”停止本地接收；关闭窗口会先取消再释放连接。取消不保证远端停止生成／计费；服务商保留请求的规则也不由本工具控制。

测试结果仅表示当次兼容调用是否成功，既不是NPC功能验收，也不是检查点2A的性能对照实验。确认后测试真实服务与开发中使用受控传输的程序自测不同；2026-10-16获准执行的2A本地实测另有上述独立报告，不归入GUI程序自测。

### 右侧诊断面板怎么看

连接测试和取消按钮已移到右侧。运行中每约50毫秒更新累计观测，结束后保留终止前阶段、HTTP状态／响应类型、响应体字节／数据块／有效事件数、独立思考字段和正文的片数／字符数、结束原因及安全异常类型。可滚动时间线记录响应头、首块数据、首个有效事件、首个思考／正文片段、结束标记与连接释放等实际里程碑。

| 面板证据 | 可以判断 | 不能直接判断 |
| --- | --- | --- |
| 尚未收到HTTP响应头 | 请求尚无已观测响应头；若ConnectError／ConnectTimeout则另有明确连接故障 | 仅凭总超时不能确认模型是否在加载、排队或计算 |
| HTTP 200，响应体0字节 | 服务已响应，但没有响应体数据到达客户端 | 不代表一定在加载或一定卡死 |
| 响应体有字节，有效事件0 | 收到数据但没有形成有效JSON流式事件，可能是心跳、不完整或不兼容格式 | 不等于已产生正文 |
| 思考字符增加，正文0字 | 已收到服务分离的思考字段，不是完全无响应 | 不展示思考原文，也不能推断具体思考内容 |
| 正文增加，未结束 | 正文可接收，尚未可靠终止 | 不代表完整调用已通过 |
| HTTP 401／403／404／429等 | 显示认证、权限、路径或模型、请求限制等排查方向 | 例如404不能只凭状态码区分路径错误和模型不存在 |

“思考”仅统计服务明确分离的reasoning_content／reasoning字符串；未提供这些字段不代表模型没有思考。响应体字节是HTTP客户端解压后的数据量，不是TCP包大小。阶段不伪装为服务端内部状态；原始响应头、错误体、请求内容、密钥和生成正文均不进入诊断时间线。不自动落盘，关闭窗口后不保留这份诊断。

正常程序调用默认不启用诊断；它不混入NPC正文流、认知反馈或记忆。输出上限64 token及总时限30秒未改变，首次加载／思考可能超过预算；先依据证据判定等待阶段，再结合本地服务日志排查。

### 思考请求开关（服务／模型支持时）

展开高级配置，在“思考请求（支持时）”选择：

| 选项 | 实际配置 |
| --- | --- |
| 模型默认 | 清空思考JSON，不主动发送思考控制；原有自定义内容会先请求确认 |
| 请求开启（medium） | 思考JSON写入reasoning_effort=medium |
| 请求关闭（none） | 思考JSON写入reasoning_effort=none |
| 自定义JSON | 保留原内容，按服务文档编辑；例如其他强度／其他服务的参数 |

开启／关闭只修改思考控制，保留其他JSON参数；移除嵌套reasoning.effort避免重复控制。保存时仍进行原有安全校验，配置文件格式不变，不新增必须迁移的字段；加载旧自定义参数不会被预设静默覆盖。恢复默认需要修正无效JSON或清空后操作，不丢失未完成输入。

这些是兼容接口请求，不是万能的模型能力开关；服务可能不支持、报错或忽略。开关型模型的medium可能仅表示开启，不保证具有“中等强度”。Ollama映射依据[官方兼容文档](https://docs.ollama.com/api/openai-compatibility)。请求关闭仍收到思考字段会提示；请求开启但无独立思考字段也会提示不能确认生效，不能把零片段当作内部完全无推理。

操作顺序：选择预设 → 保存配置 → 按需勾选内容查看 → 连接测试。保存不调用模型；不自动切换模型、查询能力或失败重试。

### 可选内容查看（仅本次测试内存）

1. 测试开始前勾选右侧“采集并查看返回内容”，展开“回复正文／服务思考字段”两个页签；默认不勾选、不采集。运行中选项固定，不能中途恢复未采集的前段。
2. 确认连接测试后，内容逐步显示。只展示服务明确返回的正文与独立思考字符串，不从正文标签反推，不代表可查看模型完整内部推理。
3. 各保留最多4096字符，超出会提示预览截断；不影响上方完整统计，也不改变模型请求的token预算。未提供思考字段时该页签为空，不伪造内容。
4. 新测试会清空旧内容；取消勾选会清空显示，关闭窗口后不保留。不自动写文件、复制到剪贴板、进入诊断时间线或NPC记忆；没有历史内容恢复功能。
5. 会遮蔽本次已知API Key的原值及未收齐的尾部分片，但不是通用敏感信息过滤。服务生成内容仍可能敏感，请谨慎截图或复制。

原“终止前阶段”被尾部用量事件覆盖的问题已修复；用量可计入事件数，但不会重新标成首个事件。

仅本次进程的密钥不能被其他进程共享；关闭独立GUI后再启动NPC，需使用系统凭据库，或本地服务不配置密钥。本轮隔离安装验证使用临时／假凭据，不读写用户真实系统凭据库。

第一次只想查看界面，可用隔离配置，不接触已有用户配置：

```powershell
python -m model_service.gui --config ./data/runtime/m1/v015-gui-preview/profiles.json
```

默认普通配置位于当前用户配置目录的model-service-kit/profiles.json，Windows通常在LOCALAPPDATA下；--config可指定位置。schema_version=2文件不保存明文密钥；复制普通配置到其他设备后，须重新输入凭据。本检查点不自动读取用户旧密钥。

检测到旧格式时正常保存／切换被阻止。选择凭据保存方式，点击“迁移旧配置”并确认，才会迁移密钥、原子替换配置并移除明文；不另建明文备份，失败保留原文件。此功能只在临时旧配置上测试过，未操作用户实际配置。

## 适用范围

- 当前有安全配置GUI、凭据引用、旧同步兼容接口和新异步纯文本流式接口；不包括独立Gateway Server、模型下载／加载、服务发现、缓存、自动重试或计费管理。NPC适配留在NPC项目，不进入本包。
- 配置界面依赖 Python 自带的 Tk；无图形桌面的环境可通过包接口管理配置。
- 公共包的版本和 NPC 项目的 `V0.1.x` 版本独立；NPC 应记录采用的包版本。
